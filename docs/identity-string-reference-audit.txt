Identity/string reference audit
Generated: 2026-07-05

Scope
=====

This file records the remaining places where resolved references still depend
on String names, or where a String name can still decide lookup/matching after
parser/name-resolution has already run.

"String-dependent" here means a semantic reference is still keyed, matched, or
recovered by String. Display names, source names, and ABI/runtime spellings are
called out separately, because those names are still required for diagnostics,
linking, generated code, and user-facing output.

Legend
======

- BLOCKER: a post-resolution semantic lookup/match can still be decided by a
  String name.
- BOUNDARY: a parser, resolver, finalization, FFI, or ABI boundary still needs
  a String spelling, but should not use it as semantic identity once metadata is
  resolved.
- DISPLAY: expected source/display/runtime spelling; keep it non-semantic.

Remaining areas
===============

--------------------------------------------------------------------

Recommended removal order
=========================

1. Declare the production invariant:
   CheckedProgram and BackendProgram must be identity-complete for term
   variables, constructors, data heads, and type binders. Any Nothing identity
   in a production semantic reference should be a validation failure unless it
   is explicitly fenced as parser/test/metadata-light input.

2. Split backend semantic references from display/runtime names:
   - BackendVar should require IdDetails in production.
   - BackendConstruct should require SymbolIdentity in production.
   - BackendDataParameterRef should require TypeBinderIdentity in production.
   - BackendTypeSubstitutionKey should stop accepting ByName for production
     checked programs.
   Keep name-only constructors only in test helpers or clearly marked boundary
   modules.

3. Replace RuntimeExternalBindingIndex's name-first API with identity-first API.
   Keep String alias maps only for resolving current surface/free variables at
   the final boundary.

4. Stop round-tripping resolved frontend references through surfaceVar runtime
   names. Add an identity-bearing lowered expression path, or convert directly
   to ElabTerm/Backend references after resolution.

5. Remove LLVM rewriteBackendVarsByName after backend conversion guarantees
   identity-complete BackendVar references.

6. Fence structural/name fallbacks behind an explicit metadata-light path, then
   make normal checked-program lowering reject missing identities.

7. After those changes, audit remaining search terms:
   - "Maybe IdDetails"
   - "Maybe SymbolIdentity"
   - "ByName"
   - "lookup...ByName"
   - "Map String" in semantic scope/env/index modules
   - "idDetailsRefMatches" fallback callers

Distance from "all references use Identity"
==========================================

Close:
- Checked term variables and runtime execution already have identity-keyed
  paths.
- ResolvedVar no longer carries its own runtime-name String field.
- CheckedBinding derives names from ResolvedVar details instead of storing a
  separate authoritative name.

Not close yet:
- Backend IR still encodes many semantic references as Maybe identity plus name.
- Finalization still exposes name-first external-binding indexes.
- Frontend elaboration still converts resolved references back into name-shaped
  surface variables.
- LLVM lowering still contains a name-based identity retrofit pass.
- Structural recursive data still has identityless/name fallback behavior.

Practical conclusion:
The remaining work is not mainly in ResolvedVar anymore. The next meaningful
speed/correctness milestone is to make Backend IR production references
identity-complete, then delete the finalization/backend/LLVM name fallback
passes that exist only because identities may be missing.
